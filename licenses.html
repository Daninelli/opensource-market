开源协议说明

本站只做收录与跳转，不托管任何项目代码。以下是对常见开源协议的通俗解释，帮助你判断「能不能改、能不能商用、要不要公开源码」。

本文只是常识性梳理，不构成法律意见。协议以各项目仓库根目录下的 LICENSE 文件原文为准；商用前请自行阅读原文或咨询律师。

本站自身的协议

开源集市的页面源码、样式与项目数据，以 MIT 协议开源。你可以自由地阅读、复制、修改、再分发，甚至拿去做自己的导航站，只需保留版权声明。

这与下面要讲的第三方项目协议是两件事，需要分开理解：

  • 本站自身的 MIT：管的是这个导航站的代码与数据；
  • 各项目的协议：管的是被收录项目自身的代码，本站不参与它们的授权。

本站收录了什么，没有收录什么

本站只收录两类信息：

  • 客观事实：项目名称、仓库地址、star 数、最近更新时间、许可证名称。这些属于事实陈述。
  • 自行撰写的简介：note_zh 由本站维护者独立撰写，不复制上游 README 原文。

本站没有收录、也没有托管：第三方项目的源代码、安装包、图标素材与文档全文。

卡片上的下载按钮是普通外链，点击后浏览器直接跳转至 GitHub / Gitee 官方服务器，字节流由原作者的服务器直接提供，本站服务器全程不参与传输，因此不构成许可证意义上的「分发」。

一句话判断

协议能商用吗改了要开源吗典型项目
MIT可以不用Medusa、Memos
Apache-2.0可以不用（但要保留声明）mall、Sa-Token
BSD-3-Clause可以不用Saleor
MPL-2.0可以改动的文件要开源Penpot
LGPL可以改库本身要开源部分工具链
GPL-2.0 / 3.0可以，但衍生作品也要 GPL要Godot、Odoo、ERPNext
AGPL-3.0可以，但提供网络服务也要开源要Grafana、Immich、Mastodon
MulanPSL-2.0可以不用hutool

宽松协议（MIT / Apache-2.0 / BSD）

最适合二次开发和商用。基本只要保留原作者的版权声明和许可证文本，就可以闭源修改、集成进商业产品。

  • MIT：最短、最宽松，几乎不限制你怎么用。
  • Apache-2.0：比 MIT 多两条——要保留 NOTICE 文件，以及明确授予专利许可。
  • BSD-3-Clause：与 MIT 接近，多一条「不能用原作者名义背书」。

弱传染协议（MPL / LGPL）

介于宽松和强传染之间，边界在「文件」或「库」这一级：

  • MPL-2.0：你修改过的那几个文件要以 MPL 开源，但项目其他部分可以闭源。
  • LGPL：动态链接使用不触发开源义务；修改库本身则要开源。

强传染协议（GPL / AGPL）

如果你的产品基于它做衍生，整个衍生作品都要以同样的协议开源。

  • GPL-2.0 / GPL-3.0：分发二进制时必须提供源码。
  • AGPL-3.0：在 GPL 基础上补了一个漏洞——即使不分发，只要通过网络提供服务，也要提供源码。做 SaaS 时要特别注意。
商用不等于侵权。GPL / AGPL 项目完全可以商用，前提是遵守它的开源义务；真正不能做的是「拿了 GPL 代码闭源卖」。

「开源」在这里指什么

本站的收录门槛是源码公开可获取，而不是严格的 OSI 开源认证。这两者有区别：

  • OSI 开源协议：MIT、Apache-2.0、GPL、AGPL、MPL、BSD 等。允许自由使用、修改、分发（部分协议带传染性或保留条款）。
  • 源码可用但非开源：BUSL（商业源码许可）、Elastic License 2.0、Sustainable Use License，以及部分项目自定义的社区协议。这类协议通常限制商业使用或托管服务，不符合 OSI 的开源定义。

本站会把后一类项目自动标注为「非开源」徽章。判定由脚本按 SPDX 标识自动完成，不依赖人工逐个核对，因此不会因为项目变多而漏标。如果你只需要严格意义上的开源项目，看到这个徽章请先查阅原仓库的许可条款。

「非开源」标记由 tools/classify-licenses.mjs 生成，随每次数据刷新自动更新。某项目的协议后续发生变化时，也会记录在详情页的「变动记录」里。

本站的收录立场

  • 本站只记录项目的协议名称，不复制、不修改、不再分发任何项目代码。
  • 「下载应用」按钮指向项目方在 GitHub / Gitee 上自己发布的 Release 资产，文件由官方服务器直接提供。
  • 协议信息以抓取时的仓库状态为准，可能滞后或存在误差；以仓库内 LICENSE 文件为准。
  • 协议分类（开源 / 非开源）由脚本自动判定，目的是帮你快速筛选，不构成法律意见。
  • 若发现标注与官方不一致，欢迎通过 Issue 指出。

常见误区

  • 「开源 = 免费 = 可以随便用」：错。开源是授权方式，不是放弃权利。
  • 「没写协议 = 公共领域」：错。没有 LICENSE 文件默认保留所有权利，不能直接用。
  • 「改了名字就不是衍生作品」：错。是否衍生看代码来源，不看名字。
  • 「自己内部用不用管协议」：GPL 一般不触发（没有分发），但 AGPL 会因为对外提供服务而触发。
